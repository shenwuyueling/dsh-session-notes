# dsh-session-notes · 会话记事便签

给 DSH Web GUI / 官方桌面客户端加一块**常驻的记事便签**：随手记下当前会话的重点（待办、结论、约束、待确认的问题），不用再回翻历史对话；便签可以拖动、可以缩放、可以折叠，并且**按会话分别保存**。

同时带一套**数据管理（清空缓存）**：看得见占用了多少浏览器存储，能按影响范围分级清理，破坏性操作都有二次确认。

- 客户端半区是**手写单文件 bundle**（`lib/client.js`），不需要任何构建工具或依赖安装。
- 宿主半区是**空实现**，只认领插件行：不注册服务、不写文件、不改 profile 配置。
- 记事存在**浏览器 localStorage**（同源持久），按会话 ID 分键。

## 环境要求

- DSH `>= 0.2.0-rc.2`（`package.json` 的 `dsh.engines.dsh`）。
- Web 端（`dsh web`）或官方桌面客户端。插件声明 `dsh.client.platform: "web"`。

## 安装

### 方式一：桌面客户端内置安装器（推荐）

官方桌面客户端读的是 `desktop` profile，官方 CLI **拒绝**写入该 profile，所以用客户端自己的插件页安装：

1. 把整个 `dsh-session-notes` 目录放到一个**长期稳定的位置**，例如：
   `C:\Users\<你的用户名>\.dsh\local-plugins\dsh-session-notes\`
2. 打开 **设置 → 插件**，用本地路径 / `link:` 方式添加包：`dsh-session-notes`。
3. **重启客户端**（客户端 bundle 在启动时合成）。

### 方式二：CLI（仅适用于 web profile）

```sh
dsh plugin --profile web add link:<插件目录绝对路径>
```

装完重启 `dsh web`（不是新起一个服务器，而是重启原来那个进程）。

### 安装后怎么确认装上了

重启并刷新页面后，右下角应出现「会话记事」便签（默认位置在鲸鱼挂件左侧、离右边缘 300px、离底边 96px）。没出现时按下文「排查」逐项检查。

## 使用

### 便签本身

| 操作 | 怎么做 |
| --- | --- |
| 记内容 | 点正文区域直接输入，**自动保存**（停止输入 0.4 秒落盘，失焦/关页面前强制落盘） |
| 移动 | 按住**标题栏**拖动；拖出屏幕会被自动夹回可视区 |
| 缩放 | 拖**右下角把手**（宽 260–720px，高 160–640px，视窗口大小自动收窄上限） |
| 折叠 / 展开 | 标题栏 `▾` / `▸`，或快捷键 **Ctrl/Cmd + Shift + N** |
| 切会话 | 便签跟随**主视图当前选中的会话**，内容自动切换；每个会话一条独立记事 |
| 状态 | 标题栏的圆点：蓝＝已绑定会话，灰＝未选中会话，红＝保存失败（存储已满） |

未选中任何会话时便签进入只读占位，不会把内容写到错误的会话里。

### 数据管理（标题栏「管理」）

打开后显示：

- **存储用量**：会话记事条数、记事合计字节、本条字节、浏览器配额已用/可用、孤儿数据条数、脏数据条数。
- **数据**：导出本条 / 导出全部（下载 JSON）、导入 JSON（按会话 ID 合并，同 ID 取 `updatedAt` 较新者）。
- **清空缓存（按影响范围）**：四档操作，分别只作用于自己声明的范围，破坏性操作**需要点两次**（第一次变成「确认…？」，4 秒内不确认自动取消）：

| 按钮 | 清掉什么 | 保留什么 |
| --- | --- | --- |
| 删除本条记事 | 当前会话的记事 | 其它会话记事、便签位置/尺寸 |
| 清空全部记事 | 所有会话记事 + 索引 | 便签位置/尺寸（**不丢你的摆放习惯**） |
| 清理孤儿数据 | 会话已不存在（被归档删除）的记事 | 现存会话的记事、便签状态 |
| 仅重置便签位置 | 便签位置、尺寸、折叠状态 | **全部记事内容** |
| 全部重置 | 记事 + 索引 + 便签状态 + 手动会话绑定 | 不涉及本插件之外的任何数据 |

- **会话绑定**：默认自动跟随主视图会话；如果某些版本里识别不到（圆点显示灰、状态写「未选中会话」），可以在「会话绑定」输入框手填会话 ID，点「恢复自动」回到自动识别。自动识别可用时永远优先自动值。

## 存储结构（清缓存时对得上）

| 键 | 内容 |
| --- | --- |
| `dsh-session-notes:v1:session:<sessionId>` | `{"text":"…","updatedAt":1234567890123}` |
| `dsh-session-notes:v1:index` | 有记事的会话 ID 数组（用于导出与孤儿判定；与真实键不符时会自动重建） |
| `dsh-session-notes:v1:panel` | `{"pos":{"x":…,"y":…},"size":{"w":…,"h":…},"collapsed":false}` |
| `dsh-session-notes:v1:manualSession` | 手动指定的会话 ID（仅在自动识别失败时生效） |

除上面这些键，插件不读写任何其它 storage 键；「全部重置」也只删这些键。

## 已知限制

- **记事属于这份浏览器存储**，不跟随账号：清空浏览器站点数据（或换浏览器 / 换端口访问）后会丢。重要内容请用「导出」留一份 JSON。
- 存储写满时正文会显示「保存失败：存储已满」，此时先「导出」，再「清空全部记事」或「清理孤儿数据」释放空间。
- 浏览器禁用 localStorage（隐私模式等）时，便签显示为只读并提示「浏览器存储不可用」。
- 多个标签页同时打开时，另一标签页的改动会通过 `storage` 事件同步到便签；但仍建议同一会话只在一个标签页里编辑。
- 会话 ID 取不到（自动识别不可用）时，如果不手动指定，便签不会写入任何内容。

## 排查

1. **便签完全没出现**：确认客户端已重启、页面已刷新（客户端 bundle 在启动时合成，改完代码需要重启宿主）。然后在 DevTools 里查 `[data-dsh-plugin="dsh-session-notes"]`：
   - 元素不存在 + 控制台有 `document.body is unavailable` → 插件在 body 就绪前被激活，报这一行；
   - 元素不存在 + 控制台没有任何 `dsh-session-notes` 输出 → 客户端半区没被挂载，检查 `dsh.client.platform` / `exports["./client"]`，以及该行是否被 profile patch 里的 `disabled` 关掉；
   - 元素存在但看不到 → 多半是被别的东西盖住或尺寸为 0，检查元素的行内 `left/top/width/height` 与层级（`z-index: 60`）。
2. **便签出现但一直显示「未选中会话」**：说明这个版本的会话目录没有发布 `retainedBy.mainView` 计数。用「管理 → 会话绑定」手填会话 ID 作为临时方案，同时记下这条现象。
3. **样式没生效（便签能拖但很丑）**：说明 `styles` 内建没注入且 DOM 兜底也没跑成，控制台会有 `stylesheet injection failed`。

## 卸载

- 桌面客户端：从 **设置 → 插件** 移除 `dsh-session-notes`；web 端：`dsh plugin --profile web remove dsh-session-notes`。
- **卸载不会清空记事数据**；要清数据先在「管理」里用「全部重置」，之后再卸载。
- 卸载后便签、键盘快捷键、注入的样式都会随之移除（`ctx.effect` 已登记清理）。

## 开发

```sh
# 跑测试（Node 18+；不需要 pnpm install，测试没有第三方依赖）
node --test test/
# 或者直接跑（自建断言与退出码）
node test/notes-core.test.mjs
```

测试通过一个桩 `window.__ModuleLoader__` 加载 **lib/client.js 本身**，再对 `exports.__core` 断言，所以跑的就是真正会下发到浏览器的代码；另外还校验 `package.json` / `cordis.patch.yml` 的挂载契约，以及 `apply()` 的挂载与卸载行为（含 `document` 缺失时的降级）。

改动时请保持：

- `package.json` 的 `name`、`cordis.patch.yml` 里 `insert[].name`、client bundle 的 `id` 三者一致；
- `lib/client.js` 不新增 `require('...相对路径')`（模块加载器只解析启动图里的模块 id）；
- 纯逻辑留在 `#region core` 区域内，并挂到 `exports.__core` 上。

## 实现说明（便于排查）

- **挂载方式**：便签不注册到任何 slot，而是在 `document.body` 上自建一个固定定位的 React root（`<div data-dsh-plugin="dsh-session-notes" data-dsh-session-notes-root>`）。这样不依赖 `shell.overlay` 这类由 shell 拥有、默认穿透点击的浮动层的激活语义，样式与层级完全由插件自己控制。在 DevTools 里用 `[data-dsh-plugin="dsh-session-notes"]` 就能定位到它。
- **样式注入**：优先用客户端内建 `styles.insert(css)`；拿不到时回退为带 `data-plugin` 标记的 `<style>` 元素，卸载时一并移除。
- **会话绑定**：每次调用都现读 `ctx.sessions.list`，因此即使面板比会话服务先就位，服务到齐后也会自动恢复绑定（不会永久空置）。
